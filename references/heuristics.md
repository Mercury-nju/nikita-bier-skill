# Product Diagnosis

This is the package author's working method, informed by the linked public principles. It is not Nikita Bier's published scoring model.

## Start With The Decision And Evidence

Name the decision: change onboarding, recruit a first network, expand acquisition, or investigate repeat use. Then identify what the user actually supplied: user behavior, cohort counts, interviews, or only an idea.

Positive interviews support a hypothesis about demand; they do not establish adoption. Sparse inputs justify candidate explanations, not a factual description of an empty feed or a definitive verdict that the product is dead.

## Qualitative Dimensions

Use only dimensions relevant to the product. Each can be `supported`, `risk`, `unknown`, or `not applicable`, with a brief evidence note. No sum, rank, or implied probability is needed.

| Dimension | Question | Useful evidence |
| --- | --- | --- |
| Demand | What outcome already matters to these users? | Repeated workarounds, actual usage, commitments, purchases |
| Orchestration | What people/content must be present for first value, and can that state be created? | Start attempts, dependencies, response times |
| Distribution | What brings the next suitable user, through which channel? | Invites accepted and activated; qualified search, sales, or paid acquisition |
| Density | Does value depend on relevant people participating together? | Active connections and interactions within the initial network |
| Shareability | Does voluntary sharing help acquire suitable users? | Shared outputs leading to visits and first value, not merely share clicks |
| Durability | What brings users back at the product's natural frequency? | Cohort repeat use, retained value, renewal, not a launch spike |

The earlier six-axis, 0-2-point rubric and its 12-point total were package-author additions without calibration. They have been removed. A confirmed failure to deliver first value should block acquisition expansion until an activation test resolves it; other strengths cannot cancel that bottleneck. An unknown is not a failure, and a non-social dimension is not a defect in a private utility.

## Locate The Bottleneck

Map the actual path: suitable audience -> entry -> first meaningful value -> repeat value. Add invitation -> accepted invitation -> new user's first value only when the social loop is relevant.

Distinguish installation and activated-cohort denominators. If 20 of 200 installers reach first value, activation is 10%. If 14 of those 20 return on day 7, conditional retention is 70%; those 14 represent 7% of installers, but total installer retention remains unknown unless returns by the other 180 were measured. The activated sample may select the most motivated users.

Inspect the largest observed loss before prescribing a fix. Low activation could reflect irrelevant content, absent peers, setup friction, targeting, or technical failure. Removing setup is one candidate intervention; necessary setup may build the relevant graph.

If no bottleneck is supported, name the leading hypotheses and choose the check that would distinguish them. Do not manufacture certainty to produce a single diagnosis.

For a multi-step social product, make the proof obligations explicit: core value, spread within the first relevant peer group, and movement to another group are different checks. Fully execute the stage being tested and keep later stages minimal where possible. Limit the list to the few conditions that can actually block the product; the “about four” guideline is a working heuristic, not a law.

## Choose An Informative Test

Specify the detail needed to run the test:

- **Audience:** one relevant network, or comparable independent networks if density is involved.
- **Intervention:** the smallest change aimed at the suspected bottleneck; keep other major conditions comparable.
- **Value event:** an observable outcome, such as a useful reply from a real peer. Define it before counting it.
- **Measurement:** event rate with denominators, time to value, repeat use, and manual work needed. Track invitations through activation when evaluating distribution.
- **Window and comparison:** fit the natural use cycle. User-level randomization in a social network can contaminate groups; use independent network-level comparisons where available.
- **Decision:** agree before the test what supports continuing, changing the hypothesis, or stopping. With little baseline data, use a pilot to estimate it; do not invent universal conversion targets or call a small sample statistically conclusive.

For consumer products, add a misuse pass to the test plan: identify likely spam, manipulation, or unintended use, then test safer defaults and affordances. Describe the risk and mitigation without giving operational abuse instructions.

Example: in a campus community, keep recruitment and real peer availability consistent while testing a revised route to the first exchange. Record the fraction of new users completing that exchange within a defined window. Follow the same cohort for repeat use. If interactions disappear when staff stop prompting, the result supports assisted demand, not yet a self-sustaining loop.

## Choose The Launch Shape

Repeated small-community testing needs enough similar communities to retry and sufficiently independent exposure. Source S04 specifies plentiful communities (more than ten), comparability, and minimal communication leakage; the numerical count is his heuristic, not a statistical requirement.

When groups overlap and value needs creators and readers together, organize a bounded activation event: commit real supply, recruit matching demand, coordinate attendance, and measure value for both sides. Broader exposure requires evidence that this network delivers value. Failed small tests alone do not justify a bigger launch.

## Transfer The Lens Carefully

For private utilities, prioritize individual payoff, repeat use, and appropriate acquisition channels. Sharing is optional and should serve a user need. For B2B workflows, distinguish invitations needed to complete a task from invitations intended to acquire another customer; measure workflow outcomes and organizational adoption. Explain which consumer-social assumptions do not transfer.
